# Agent Profile: `sopheak/sp-laravel-api`

This repository contains a Laravel package that provides a **unified, dynamic API layer** on top of Eloquent models and database tables. The agent working on this repo should understand and respect the following principles.

## Mission

- Maintain and extend a **config-driven API engine** built around `RecordTableType` and `RecordFunctionType`.
- Preserve **backward compatibility** for existing API consumers (response shape, error codes, and config semantics).
- Keep the package **framework-idiomatic** for Laravel 11+/12+, with strict typing and PSR-12 style.

## Core Responsibilities

- Work primarily inside `src/` and `config/` to:
  - Evolve the dynamic CRUD system (`RecordService`, `CoreRecordController`).
  - Maintain query filtering, relationship resolution, and audit logging.
  - Keep OpenAPI generation (`OpenApiService`) in sync with runtime behavior.
  - Maintain console tooling (e.g. `sync-record-columns`) and schema utilities.
- Ensure all new behavior is **covered by tests** (Feature or Unit) where it touches core flows.
- Keep **config-based APIs** simple to consume for application developers.

## Development Guidelines

- **Language & Style**
  - PHP 8.2+ with strict types where possible.
  - Follow Laravel conventions and PSR-12 formatting.
  - Prefer named arguments for complex constructors/config objects.

- **Architecture**
  - Keep `RecordTableType` and related `Types/` classes as the **single source of truth** for table configuration.
  - Use `Services/` for orchestration (e.g. `RecordService`, `AuditLogService`, `RecordApiResponseService`).
  - Use `Support/` and `Utilities/` for reusable helpers (filters, schema registry, cache helpers).
  - Console commands should remain **safe and idempotent**, with clear console output.

- **Testing & Quality**
  - Prefer **small, targeted tests** in `tests/Unit` for pure logic.
  - Add **Feature tests** under `tests/Feature` when changing API behavior or HTTP contracts.
  - Use existing scripts:
    - `composer test`
    - `composer analyse`
    - `composer format` (Rector) for bulk refactors when needed.

## API Contract Expectations

- Standard API responses use `RecordApiResponseService` and must include:
  - `success` (boolean)
  - `errorCode` (integer from `HttpErrorCodeConstant`)
  - `data`
  - `meta.request_id` when available
- Error responses must additionally include:
  - `message` (human-readable)
  - `errors` (array or structured details)
- The OpenAPI spec generated by `OpenApiService` must reflect **exactly** the runtime JSON structure.

## When Editing

- Prefer **augmenting configuration** (e.g. new options on `RecordTableType`) over hardcoding behavior.
- When introducing new behavior:
  - Add appropriate configuration knobs in `config/record.php` or related config areas.
  - Document the behavior in the OpenAPI description or existing docs where relevant.
- For console commands (e.g. `sp-laravel-api:sync-record-columns`):
  - Keep output clear and informative.
  - Support safe flags like `--force` and targeted operations like `--table`.
