## Decided
- All 13 reports of 2026-10-26 are fixed in the working tree (unreleased). `eq`/`neq` now compare the whole value; only `eq.(a,b)` is a list, and double-quoted items work in `in`/`not_in`/`or=()` (`QueryBuilderFiltersUtils::splitList`, `equalityOperand`). This breaks `eq.a,b` callers on purpose: the report's done-when requires `eq.Acme, Inc.` to match exactly.
- Bulk upsert sends one batched `upserted` RecordMutated but still writes no audit rows or per-row hooks (one raw upsert). Docs say so. Force delete still broadcasts `deleted`; `force_deleted` was removed from the docs rather than added to the code, to keep clients working.
- Per-page default is the new `record.default_per_page` (25), applied only when `page`/`cursor` is sent; a request with no paging parameter still uses `limit_max`.

## Tried and ruled out
- Adding `not_like` -> `like` style reverse negations for every `not_*` operator: skipped, a `not.` on those answers 422 instead.

## Watch out
- `secret` on `sp_webhook_endpoints` is a hidden column, and `RecordService::executeGetByFilter` strips hidden columns, so `WebhookTrigger` reads the secret with `DB::table()`; reading it through the API layer would sign with an empty string.
- Package-route 404/429 envelopes are a `renderable` on the host's exception handler, limited to routes carrying the `request.id` middleware.
- Attachment URLs gained the `rpc` segment, so tests asserting `/sp_attachments/{id}/view` had to change.
